# Figma 디자인 분석

> 기준: Figma 파일 "Campus Hangout (복사)"의 캔버스 전체를 내보낸 PNG (2026-11-13, 8000×3722)
> 작은 글씨는 일부 읽을 수 없어서, **색 hex 값과 정확한 문구는 원본 데이터를 받은 뒤 확정**합니다. ([tools/figma](../../tools/figma/README.md) 참고)
> 읽기 불확실한 부분은 "(판독 불확실)"로 표시했습니다.

## 1. 서비스 개념

| 항목 | Figma 내용 |
|---|---|
| 한 줄 소개 | Make friends on campus / A new place. A familiar feeling. |
| 브랜드 가치 | Connection · Openness · Togetherness |
| 핵심 흐름 | 모임 중심 · 친구 유지 · 노크로 시작하는 1:1 대화 |
| "방"의 의미 | 단순 채팅방이 아니라 **날짜·시간·장소·정원이 있는 모임**. 방마다 그룹 채팅이 있음 |
| 하단 탭 | Explore rooms(홈) · My chats · Find friends · My campus → 현재 앱 코드의 탭 4개와 같음 |

## 2. 화면 목록

상태: ● 디자인 완료 / ◐ 와이어프레임(색·스타일 없음) / ○ 없음

### A. 시작 (Phase 1)
| 화면 | 상태 | 내용 |
|---|---|---|
| Splash | ● | 로고, "Make friends on campus" |
| Onboarding 3장 | ● | Find your people / Join in, your way(실명·익명) / Meet for real(모임 카드), 건너뛰기 |

### B. 가입·로그인 (Phase 1)
| 화면 | 상태 | 내용 |
|---|---|---|
| Log in | ● | 이메일·비밀번호, 비밀번호 찾기, 가입하기, EN/KO 전환, 입력 오류 상태 |
| Create account (1/4 계정) | ● | 이메일, 비밀번호, 약관 동의 |
| Your profile (2/4 프로필) | ● | 이름, 국적, 전공, 사용 언어(여러 개) |
| Verify student ID (3/4 학생증) | ● | 사진 업로드 → 미리보기 "Looking good?" → 제출, 카메라 권한 안내 |
| Waiting for approval (4/4 승인) | ● | 제출 → 검토 중 → 승인 타임라인, "보통 24시간 이내" |
| 반려 → 재업로드 | ● | "사진이 흐려서 읽을 수 없어요" 같은 사유 표시 |
| 세션 만료 → 다시 로그인 | ● | 다이얼로그 |
| Verify email (6자리 코드) | ● | 만료 타이머, 재전송, 다른 이메일 사용 → **기존 결정과 다름 (4장 1번)** |
| 관리자 학생증 심사 | ○ | **Figma에 없음 (4장 3번)** |

### C. 홈·탐색 (Phase 3)
| 화면 | 상태 | 내용 |
|---|---|---|
| Explore rooms | ● | "Who's hanging out today?", 이번 주 인기(가로 카드), Rooms for you, 카테고리 칩, 검색·알림 아이콘, + 방 만들기 버튼 |
| 카테고리 필터 결과 | ● | 예: Food rooms |
| Search rooms | ● | 최근 검색, 카테고리별 찾기, 결과 없음 |
| 로딩·오류·오프라인 | ● | 스켈레톤, "A little pause in your plans"(다시 시도), 오프라인 배너 |
| 알림 권한 안내 | ● | 모임 알림·노크 알림 허용 다이얼로그 |

### D. 모임 방 (Phase 3)
| 화면 | 상태 | 내용 |
|---|---|---|
| Create room | ● | 제목(최대 40자), 카테고리(1개), 태그(최대 3개), 설명, 날짜, 시간(KST), 장소, 정원, 참여 방식(실명/익명), 바로 참여/방장 승인 스위치, 입력 오류 상태 |
| Room details | ● | 상태 5가지: I'm in!(바로 참여) / Request to join(승인제) / 요청 보냄(대기) / Room is full / 참여 완료 → Open chat |
| 참여 시트 | ● | Join as yourself(프로필 공개) / Join with a nickname(무작위 닉네임) |
| 참여 완료 | ● | "You're in. Say hello!" → 채팅 열기 / 계속 둘러보기 |

### E. 방장 (Phase 3)
| 화면 | 상태 | 내용 |
|---|---|---|
| My rooms, Manage room | ◐ | 내가 만든 방, 참여자 수, 대기 중인 요청 수 |
| Join requests | ◐ | 요청자별 수락/거절, 프로필 보기 |
| Request accepted / declined, Your room is ready | ◐ | 결과 안내 |

팀 메모에 있던 **"Request Sent 이후 수락 화면 없음"**은 이 와이어프레임으로 흐름은 채워졌지만, 아직 디자인 스타일이 적용되지 않았습니다.

### F. 채팅 (Phase 4)
| 화면 | 상태 | 내용 |
|---|---|---|
| My chats | ● | 대화 목록(방·1:1), Message requests 버튼, 빈 상태 → 홈으로 |
| 방 채팅 | ● | 말풍선, 시스템 메시지, 모임 정보 카드, + 메뉴(사진·위치) |
| Room menu | ● | 참여자, 알림 끄기, 신고, 나가기 |
| Participants, 신고·나가기 다이얼로그 | ● | 신고 사유 선택 |
| 사진·위치 공유 | ◐ | Share a photo / Share a location |

### G. 친구·노크 (Phase 5)
| 화면 | 상태 | 내용 |
|---|---|---|
| Find friends | ● | 탭: 추천 / 내 친구 / 노크, "관심사·언어 기반 추천" |
| Friend profile | ● | 소개, 사용 언어, 공통 관심사, 노크 버튼 |
| Send a friendly Knock | ● | 메시지를 써서 보내는 시트 → "Knock sent" 안내 |
| Your Knocks | ● | 받은 노크 수락/거절 |
| Friend requests | ◐ | 친구 요청 수락/거절/취소, "친구 요청은 노크와 별개"(판독 불확실) |
| Message request | ◐ | 답장/삭제/신고 → 1:1 대화 시작 |

### H. 마이 캠퍼스 (Phase 2)
| 화면 | 상태 | 내용 |
|---|---|---|
| My campus | ● | 프로필 카드, 통계(방·친구·모임 수), 메뉴(프로필 수정·내 방·알림·언어), 빈 상태 |
| Edit profile | ● | 아바타 배경색, 이름, 전공, 상태 메시지, 관심사 |
| Choose interests | ◐ | 6개 분류(Food & Cafe, Study & Language, Hobbies & Culture, Sports & Outdoors, Travel & Explore, Campus Life) |
| Notifications 설정 | ● | 채팅 메시지, 새 노크, 친구 요청 수락, 모임 알림, 추천 방, 캠퍼스 소식 |
| App language | ● | English / 한국어 |
| Decorate profile | ● | 스티커를 끌어다 붙이는 프로필 보드 |

### I. 공통
- 다크 모드 버전: 홈, 방 상세, 채팅, 친구, 마이
- 한국어 버전 화면, 디자인 시스템(컴포넌트, 변수), 브랜드 아이덴티티, Handoff notes

## 3. 디자인 시스템 변경점 (코드 반영 대기)

**Handoff notes ("warm & playful")**
- 기존 변수 이름은 그대로 두고 값만 바꿨습니다. 앱 코드의 토큰 이름(`Blue500`, `Coral500` 등)과 같은 체계입니다.
- 읽힌 값

| 토큰 | Figma 값 | 현재 코드 |
|---|---|---|
| Coral/50 | `#FFF0EB` | 같음 |
| Coral/200 | `#FFB59F` | 같음 |
| Coral/500 | `#FF7A59` | 같음 |
| Coral/900 | `#5C1A08` | 같음 |
| Gray/50 | `#FFFAF7` (따뜻한 흰색) | `#F6F7F9` → **변경 필요** |
| Blue 계열 | 판독 불가 | 원본 데이터로 확정 |

- 역할 매핑도 일부 바뀌었습니다(판독 불확실): primaryContainer·outline → Coral/200, surfaceVariant·secondaryContainer → Coral/50

**브랜드 아이덴티티**
- Blue는 주 인터페이스색(앱 아이콘 배경과 같은 진한 파랑 계열), Orange(코럴)는 연결을 나타내는 따뜻한 강조색으로 조금만 씁니다.
- 앱 배경은 연한 파랑입니다.
- 공식 로고: 말풍선 안의 파란 아기 용 캐릭터. "제공된 원본 그대로 쓰고, 자르거나 다시 그리지 말 것" → **원본 이미지 파일이 필요**합니다. 지금 앱 아이콘은 임시입니다.

## 4. 기존 로드맵과 다른 점, 결정할 것

| # | Figma | 기존 결정 | 제안 |
|---|---|---|---|
| 1 | 이메일 인증코드 화면 있음 | 학교 메일 미사용, 학생증 + 관리자 승인 | **이 화면은 만들지 않음**. 이메일은 로그인 아이디로만 사용 |
| 2 | 승인 대기 화면에 "결과를 이메일로 알려 드림"(판독 불확실) | 메일 발송 없음 | 문구를 "앱 알림으로 알려 드림"으로 바꿔 달라고 디자인 수정 요청 |
| 3 | 관리자 심사 화면 없음 | 앱 안 관리자 전용 화면 | 기존 디자인 컴포넌트로 3개 화면(대기 목록, 학생증 보기·승인/반려, 반려 사유)을 구성 |
| 4 | 방장 수락 화면은 와이어프레임만 | - | 개발은 와이어프레임 기준으로 먼저 진행, 디자인 스타일은 나중에 맞춤 |
| 5 | 친구 요청과 노크가 따로 있음 | 노크 = 1:1 대화 요청 | **하나로 합치기 제안**: 노크 = 메시지를 담은 친구 요청, 수락하면 친구 + 1:1 대화 |
| 6 | 비밀번호 방, 방장 위임·공지 없음 | Phase 3에 포함 | 로드맵에서 제외 |
| 7 | 카테고리 6개 + 태그 | 임시 카테고리 9개 | Figma 6개로 맞추고 DB 테이블로 관리 (운영 중 추가 가능) |
| 8 | 노크·친구는 실명 프로필로 보임 | 익명 노크 → 동의 시 실명 공개 | 노크는 실명 기능으로 단순화 (익명은 익명방에서만) |
| 9 | 방이 "모임"(날짜·시간·장소·정원) | 일반 오픈채팅방 | 모임 필드 추가, 정원 마감·지난 모임 처리 |
| 10 | Edit profile에서 이름을 고칠 수 있음 | 이름은 학생증으로 확인된 값 | 이름 칸은 읽기 전용(인증 표시)으로 보여 줌 |
