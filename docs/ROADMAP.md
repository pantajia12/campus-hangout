# Campus Hangout 로드맵 (v3)

> v3에서 달라진 점
> - 앱 이름 확정: **Campus Hangout** (패키지 `com.campushangout`)
> - 인프라: Oracle Cloud 대신 **Azure for Students** (학교 메일 인증만으로 가입, 카드 불필요)
>   - VM B1s 1대 + 관리형 PostgreSQL + Blob Storage, 모두 12개월 무료 범위
>
> v2에서 달라진 점
> - 가입: 학교 메일 인증 대신 **학생증 사진 + 학번 제출 → 관리자 승인** (에브리타임·노크 방식)
> - **익명 / 실명 기능 모두 지원** (방 단위로 익명방·실명방 선택)
> - 언어: 앱과 서버 모두 **Kotlin**
> - 메일(SMTP) 발송은 필수 기능에서 제외했습니다. 승인 결과는 앱 화면에서 보여 주고, Phase 6부터는 푸시 알림으로도 알려 줍니다.

## 개발 방식: 큰 틀 → 세부

각 Phase는 아래 세 번의 패스로 진행합니다. 한 번에 완성하지 않고, 사람이 개발하듯 점점 촘촘하게 만듭니다.

1. **뼈대 패스**: 패키지, 화면, 엔드포인트 껍데기를 만듭니다. 고정값을 반환해도 됩니다. 흐름이 끝까지 이어지는지 먼저 확인합니다.
2. **기능 패스**: DB 테이블, 실제 로직, 앱 ↔ 서버 연결을 붙입니다.
3. **다듬기 패스**: 입력 검증, 에러 처리, 테스트, UI를 정리합니다.

Phase 하나는 GitHub Milestone 하나입니다. Phase가 끝나면 `v0.N.0` 태그와 Release를 남깁니다.

## 전체 일정 한눈에 보기

| Phase | 내용 | 태그 | 과제 요구사항 |
|---|---|---|---|
| 0 | 프로젝트 뼈대 | `v0.0.1` | GitHub 코드 관리 |
| 1 | 학생증 인증 가입 · 로그인 · 관리자 승인 | `v0.1.0` | Login & user management |
| 2 | 프로필 꾸미기 · 관심사 (실명/익명 프로필) | `v0.2.0` | 프로필·관심사 수정 창, CRUD |
| 3 | 카테고리 오픈채팅방 (익명방/실명방) | `v0.3.0` | 채팅방 생성·참여, CRUD |
| 4 | 실시간 채팅 → **MVP** | `v0.4.0` | 온라인 소통 |
| 5 | 친구 추천 · 노크 | `v0.5.0` | 핵심 로직 직접 구현 |
| 6 | 안전 · 알림 · 다국어 | `v0.6.0` | 외부 상용 API 활용 |
| 7 | 운영 배포 · 품질 · 출시 | `v1.0.0` | - |

Phase 0–4가 끝나면 과제의 필수 요구사항을 모두 충족합니다. Phase 5–7은 완성도와 차별화를 위한 단계입니다.

## Phase 0 — 프로젝트 뼈대 → `v0.0.1` ✅

- 문서: 로드맵, 개발 규칙, 아키텍처·ERD 초안, 무료 클라우드 가입 가이드
- 인프라: 로컬 개발용 Docker Compose (PostgreSQL, Redis)
- 서버: Spring Boot(Kotlin) 프로젝트, 공통 응답 포맷, 전역 예외 처리, `GET /api/v1/ping`
- 앱: Compose 단일 Activity, 디자인 토큰 기반 테마, 하단 탭 4개(홈·채팅·친구·마이)와 빈 화면
- CI: GitHub Actions에서 서버 빌드·테스트, 앱 빌드·린트
- 완료 기준: CI 통과, 앱 실행 시 탭 4개 이동 가능

## Phase 1 — 학생증 인증 가입 · 로그인 · 관리자 승인 → `v0.1.0`

**가입 흐름**
1. 앱에서 계정 정보(로그인 아이디, 비밀번호)를 입력합니다.
2. 학적 정보(실명, 학번, 학과, 국적)를 입력하고 학생증 사진을 올립니다. 실물 학생증 사진이나 모바일 학생증 캡처 모두 됩니다.
3. 계정이 **심사 대기** 상태가 되고, 앱에는 "승인 대기 중" 화면이 보입니다.
4. 관리자가 관리자 화면에서 학생증과 입력 정보를 대조한 뒤 **승인** 또는 **반려(사유 입력)** 합니다.
5. 승인되면 프로필 온보딩으로 넘어가고, 반려되면 사유를 확인하고 다시 제출합니다.

**작업**
- 뼈대: `auth`, `verification`, `admin` 패키지와 엔드포인트 껍데기, 앱 로그인·가입·대기 화면 틀
- DB: `users`(상태: 심사 대기/승인/반려/정지/탈퇴, 권한: USER/ADMIN), `student_verifications`, `refresh_tokens`
- 서버
  - 가입(학생증 업로드 포함), 로그인(JWT access/refresh), 토큰 재발급(rotation), 로그아웃, 내 계정 상태 조회, 재제출, 탈퇴
  - 관리자: 심사 대기 목록, 상세(학생증 이미지는 만료되는 임시 URL로만 열람), 승인/반려
  - 파일 저장소 추상화: `StorageService` 인터페이스 (로컬=디스크, 운영=Azure Blob Storage)
- 앱: Hilt·Retrofit 도입, 토큰 암호화 저장, 가입 3단계 화면, 승인 대기·반려 화면, 관리자 전용 심사 화면
- 인프라: Azure에 첫 배포 (이때부터 실기기 여러 대로 테스트)
  - VM(B1s)에 Nginx + 서버 + Redis, DB는 Azure Database for PostgreSQL
  - VM 메모리가 1GB라서 JVM 힙 제한(약 384MB)과 스왑 2GB 설정
  - GitHub Actions에서 서버 이미지를 빌드해 VM에 배포하는 스크립트
- 개인정보: 학생증 이미지는 비공개 컨테이너에 저장하고 심사 후 삭제합니다. 학번은 중복 가입 방지용 해시와 입학 연도만 보관합니다.
- 완료 기준: 가입 → 승인 → 로그인 → 자동 로그인, 반려 → 재제출 흐름 동작, 인증 API 통합 테스트 통과

## Phase 2 — 프로필 꾸미기 · 관심사 → `v0.2.0`

- 실명 프로필: 학생증으로 검증된 이름·학과·학번 연도(예: 26학번)는 사용자가 직접 수정할 수 없고, 사진·소개·국적·사용 언어(모국어/배우는 언어+수준)·관심사는 자유롭게 편집합니다.
- 익명 프로필: 기본 익명 닉네임과 아바타를 정합니다. 익명방에 들어갈 때 기본값으로 쓰입니다.
- DB: `profiles`, `interests`(카테고리, 한/영 이름, seed 데이터), `user_interests`, `user_languages`
- 서버: 프로필 CRUD, 이미지 업로드, 관심사 설정, 공개 범위를 적용한 타인 프로필 조회
- 앱: 승인 직후 온보딩(사진 → 소개·국적 → 언어 → 관심사 칩), 내 프로필, 프로필 수정 화면, 타인 프로필 화면
- 디자인: 프로필 카드, 관심사 칩, 국기 배지, 인증 배지 컴포넌트
- 완료 기준: 프로필·관심사 CRUD를 앱에서 모두 수행

## Phase 3 — 카테고리 오픈채팅방 (익명방/실명방) → `v0.3.0`

- 방을 만들 때 **실명방** 또는 **익명방**을 고르고, 만든 뒤에는 바꿀 수 없습니다. 이미 익명으로 대화한 사람이 공개되면 안 되기 때문입니다.
  - 실명방: 검증된 이름·학과·국적 배지가 보입니다.
  - 익명방: 방마다 따로 정하는 닉네임과 기본 아바타만 보입니다. 서버 응답에 실제 사용자 ID를 넣지 않고 방 내부 멤버 ID만 내려 줍니다.
- DB: `room_categories`, `chat_rooms`(모드: REAL_NAME/ANONYMOUS), `room_members`(역할, 방별 닉네임, 마지막으로 읽은 메시지)
- 서버: 방 생성/목록/검색(카테고리·키워드·언어, 커서 페이지네이션)/상세/수정/삭제, 참여/퇴장, 정원, 비밀번호 방, 방장 권한(공지·강퇴·위임)
- 앱: 카테고리 탭 홈, 무한 스크롤 목록, 검색, 방 만들기(모드 선택), 입장 전 미리보기, 익명방 닉네임 설정, 내 채팅방 목록
- 완료 기준: 방 CRUD와 참여/퇴장 동작, 익명방 API 응답에 실제 사용자 정보가 없음을 테스트로 확인

## Phase 4 — 실시간 채팅 → `v0.4.0` = MVP

- DB: `messages` (`room_id, id` 인덱스)
- 서버: WebSocket(STOMP) + JWT 핸드셰이크, 구독할 때 방 멤버 권한 검증, 메시지 저장 후 Redis Pub/Sub로 브로드캐스트, 이전 메시지 커서 조회, 읽음 처리·안 읽은 수, 입·퇴장 시스템 메시지, 메시지 수정·삭제
- 앱: 채팅 화면(말풍선, 날짜 구분선, 이미지 전송, 안 읽은 사람 수), 재연결·재전송, Room DB 대화 캐시, 목록 배지
- 완료 기준: 폰 두 대로 실시간 대화, 앱 재실행 후에도 대화 유지

## Phase 5 — 친구 추천 · 노크 → `v0.5.0`

- 추천 알고리즘(직접 구현): 관심사 겹침(Jaccard) + 언어교환 궁합(내가 배우는 언어 = 상대 모국어) + 학과·학번 + 최근 활동, 차단 사용자 제외
- 관심사 기반 추천 채팅방
- 노크: 1:1 대화 요청. 익명으로 시작할 수 있고, **양쪽이 모두 동의하면 실명을 공개**합니다.
- 친구 목록, 차단
- 완료 기준: 추천 알고리즘 단위 테스트

## Phase 6 — 안전 · 알림 · 다국어 → `v0.6.0`

- 신고(사용자·메시지·방)와 관리자 처리. 익명 메시지도 관리자는 실제 작성자를 확인할 수 있습니다.
- 제재(정지), 금칙어 필터
- FCM 푸시: 새 메시지, 노크, 가입 승인·반려 결과
- UI 다국어(한/영 + 추가 언어), 메시지 번역 버튼(외부 번역 API)
- 비밀번호 재설정
- 완료 기준: 앱을 종료한 상태에서도 푸시 수신, 신고 → 제재 흐름 동작

## Phase 7 — 운영 배포 · 품질 · 출시 → `v1.0.0`

- 운영: HTTPS(Nginx + Let's Encrypt), main 머지 시 자동 배포, DB 백업(관리형 PostgreSQL 자동 백업 + 주기적 덤프를 Blob에 보관)
- 품질: 부하 테스트(k6), 에러 로그 수집, 다크모드·접근성 점검, 디자인 다듬기
- 출시: 서명된 APK/AAB, README, 시연 영상, 발표 자료

## 무료 클라우드 자원 배분 계획 (Azure for Students)

학생 구독 혜택: 크레딧 US$100 (12개월, 재학 중 매년 갱신) + 12개월 무료 서비스

| 자원 | 무료 범위 | 용도 |
|---|---|---|
| VM B1s 1대 (1 vCPU / 1GB) | 월 750시간 | Nginx + 서버 + Redis (Docker Compose) |
| PostgreSQL Flexible Server B1MS | 월 750시간 + 32GB | 주 데이터베이스 |
| Blob Storage | 5GB | 프로필·채팅 이미지(공개), 학생증 이미지(비공개), DB 덤프 |

무료 범위를 넘는 사용(트래픽 등)은 크레딧에서 빠지고, 카드가 없으니 요금이 청구되지는 않습니다.
가입 방법과 대안(Render + Neon)은 [docs/guides/azure-for-students-setup.md](guides/azure-for-students-setup.md)를 보세요.
