# Campus Hangout 로드맵 (v4)

> **v4에서 달라진 점: Figma 디자인 반영** ([분석 문서](design/figma-review.md))
> - 서비스 개념 확정: **모임 중심 · 친구 · 노크로 시작하는 1:1 대화**
> - "방"은 날짜·시간·장소·정원이 있는 **모임**입니다. 참여 방식은 (실명/익명) × (바로 참여/방장 승인)
> - 기능마다 우선순위 표시: **[필수] → [권장] → [선택]** 순서로 만들고, 기간이 모자라면 뒤에서부터 뺍니다
> - **확장성·수정 가능성 원칙**을 모든 Phase에 적용합니다
> - Figma에 없거나 다른 부분(이메일 인증, 관리자 화면, 친구 요청/노크 중복 등)은 [결정할 것](#결정할-것)에 정리
>
> 이전 변경: v3 앱 이름 Campus Hangout·운영 클라우드 변경 / v2 학생증 + 관리자 승인 가입, 익명·실명, Kotlin, 메일 발송 제외

## 공통 원칙

### 개발 방식: 큰 틀 → 세부
각 Phase는 세 번의 패스로 진행합니다.
1. **뼈대 패스**: 패키지, 화면, 엔드포인트 껍데기. 고정값을 반환해도 됩니다. 흐름이 끝까지 이어지는지 먼저 확인합니다.
2. **기능 패스**: DB 테이블, 실제 로직, 앱 ↔ 서버 연결.
3. **다듬기 패스**: 입력 검증, 에러 처리, 테스트, Figma와 화면 대조.

Phase 하나는 GitHub Milestone 하나이고, 끝나면 `v0.N.0` 태그와 Release를 남깁니다.
push 전에는 항상 [로컬 테스트 가이드](guides/local-testing.md)의 체크리스트를 직접 확인합니다.

### 확장성·수정 가능성 원칙
| # | 원칙 | 예 |
|---|---|---|
| 1 | **선택지는 코드가 아니라 데이터로** | 카테고리·태그·관심사·신고 사유·알림 종류는 DB 테이블 + 초기 데이터. 앱은 서버에서 받아 표시하므로, 운영 중 추가·수정해도 앱을 다시 배포하지 않습니다 |
| 2 | **기능 스위치** | [권장]·[선택] 기능은 서버 설정(`features.*`)과 앱 빌드 설정으로 켜고 끌 수 있게 만듭니다. 시간이 모자라면 끄고 출시합니다 |
| 3 | **API 하위 호환** | `/api/v1`에서는 필드 추가만 하고, 삭제·이름 변경이 필요하면 `/api/v2`를 만듭니다 |
| 4 | **DB 변경은 마이그레이션 파일로만** | Flyway `V2__...sql`처럼 순서대로 쌓습니다. 이미 적용된 파일은 고치지 않습니다 |
| 5 | **디자인 값은 토큰으로** | 색·간격·글꼴은 Figma 변수와 같은 이름의 토큰으로만 씁니다. Figma가 바뀌면 토큰 파일만 고칩니다 |
| 6 | **문구는 리소스로** | 화면 문구는 `strings.xml`(영/한). 서버 오류는 코드로 보내고 문구는 앱이 정합니다 |
| 7 | **공통 UI는 컴포넌트로** | 버튼·카드·칩·시트는 `designsystem`의 `Ch` 컴포넌트. 화면은 조합만 합니다 |
| 8 | **기능별 경계** | 서버는 기능별 패키지로 나누고, 다른 기능의 DB 테이블을 직접 건드리지 않고 서비스를 거쳐 호출합니다. 나중에 떼어 내기 쉽습니다 |
| 9 | **외부 서비스는 인터페이스 뒤에** | 파일 저장, 푸시, 번역은 인터페이스로 감싸서 업체를 바꿔도 나머지 코드는 그대로 둡니다 |
| 10 | **상태 변화는 한곳에서** | 계정 상태, 참여 요청 상태, 노크 상태는 enum과 "허용되는 전이" 함수 하나로 관리합니다 |

### 우선순위 표기
| 표기 | 뜻 |
|---|---|
| [필수] | 과제 요구사항이거나 핵심 흐름. 반드시 만듭니다 |
| [권장] | 있으면 완성도가 크게 올라갑니다 |
| [선택] | 시간이 남으면 만듭니다. 기능 스위치로 끌 수 있게 둡니다 |

## Phase 0 — 프로젝트 뼈대 → `v0.0.1` ~ `v0.0.5` ✅
- 문서(로드맵, 개발 규칙, 아키텍처, 테스트 가이드), 로컬 DB용 Docker Compose
- 서버: Spring Boot(Kotlin), 공통 응답 형식, 전역 예외 처리, `GET /api/v1/ping`
- 앱: Compose, 디자인 토큰 테마(라이트/다크), 하단 탭 4개
- CI: 서버 빌드·테스트, 앱 빌드·린트·테스트

## Phase 1 — 가입 · 로그인 · 학생증 승인 → `v0.1.0`

**가입 흐름 (Figma 기준 4단계)**
1. **계정**: 이메일(로그인 아이디), 비밀번호, 약관 동의
2. **프로필**: 이름, 국적, 전공, 사용 언어
3. **학생증**: 촬영 또는 사진 선택 → 미리보기 → 제출
4. **승인 대기**: 제출 → 검토 중 → 승인 타임라인. 반려되면 사유를 보고 다시 올립니다

**작업**
- [필수] 디자인 동기화 (뼈대 패스 첫 작업)
  - Figma 확정값으로 색 토큰 갱신 (Gray/50 따뜻한 흰색, Blue 계열 등)
  - 공식 로고로 앱 아이콘 교체
  - 공통 컴포넌트 추가: `ChButton`, `ChTextField`, `ChStepIndicator`, `ChDialog`
- [필수] 로그인(입력 오류 상태), 가입 4단계, 승인 대기, 반려 → 재업로드, 세션 만료 → 다시 로그인, 로그아웃, 탈퇴
- [필수] 관리자 심사: 앱 안 관리자 전용 화면 3개 (대기 목록, 학생증 보기·승인/반려, 반려 사유). Figma에 없어서 기존 컴포넌트로 구성
- [권장] Splash, 온보딩 3장 + 건너뛰기, 카메라 권한 안내
- 서버
  - DB: `users`(상태: 심사 대기/승인/반려/정지/탈퇴, 권한: USER/ADMIN), `profiles`(가입 때 이름·국적·전공 저장), `user_languages`, `student_verifications`, `refresh_tokens`
  - API: 가입, 로그인(JWT access/refresh), 토큰 재발급, 로그아웃, 내 상태 조회, 재제출, 탈퇴, 관리자 심사 목록·상세·승인·반려
  - 파일 저장소 인터페이스 `StorageService` (로컬=디스크, 운영=클라우드 저장소)
- 인프라: 첫 서버 배포 (클라우드 결정 후)
- 개인정보: 학생증 이미지는 비공개 저장소에 두고 심사 후 삭제, 학번 원문은 저장하지 않음
- 완료 기준: 가입 → 승인 → 로그인 → 자동 로그인, 반려 → 재제출 흐름 동작, 인증 API 통합 테스트 통과

## Phase 2 — 마이 캠퍼스: 프로필 꾸미기 · 관심사 → `v0.2.0`
- [필수] My campus: 프로필 카드, 통계(참여한 방·친구·모임 수), 메뉴, 빈 상태
- [필수] Edit profile: 아바타 배경색, 이름, 전공, 상태 메시지, 관심사
- [필수] Choose interests: 6개 분류에서 선택 (분류와 항목은 DB 데이터)
- [필수] 앱 언어 바꾸기 (English / 한국어, 앱 안에서 바로 적용)
- [권장] 알림 설정 화면 (설정 저장까지. 실제 푸시는 Phase 6)
- [선택] Decorate profile: 스티커 프로필 보드
- 서버: `categories`, `tags`(관심사 항목), `user_interests`, `notification_settings`, 프로필 CRUD, 프로필 사진 업로드, 공개 범위를 적용한 타인 프로필 조회
- 완료 기준: 프로필·관심사 생성/조회/수정/삭제를 앱에서 모두 수행

## Phase 3 — 모임 방: 만들기 · 둘러보기 · 참여 · 방장 승인 → `v0.3.0`
- [필수] Create room: 제목(최대 40자), 카테고리(1개), 설명, 날짜, 시간(KST), 장소, 정원, 참여 방식(실명/익명), 바로 참여/방장 승인. 입력 검증(지난 날짜 금지 등)
- [필수] 방 수정·삭제: Figma에 수정 화면이 없어서 만들기 화면을 수정 모드로 재사용
- [필수] Explore rooms: 이번 주 인기, 나를 위한 방(관심사 기준 정렬), 카테고리 칩 필터
- [필수] Room details 상태 5가지: 바로 참여 / 참여 요청 / 요청 보냄(대기) / 정원 마감 / 참여 완료
- [필수] 참여 시트: 실명으로 참여 / 닉네임으로 참여(무작위 닉네임 생성)
- [필수] 방장: 내 방, 방 관리, **참여 요청 수락·거절** (Figma 와이어프레임 기준)
- [권장] Search rooms(최근 검색), 결과 없음·로딩·오류 상태
- [선택] 태그 최대 3개, 오프라인 배너(마지막으로 본 방 보여 주기)
- 서버
  - DB: `chat_rooms`(종류: 모임/1:1, 모드: 실명/익명, 참여 정책: 바로/승인, 일시, 장소, 정원, 상태), `room_members`, `room_join_requests`, `room_tags`
  - 익명방 응답에는 실제 사용자 ID 대신 방 안에서만 쓰는 멤버 ID만 담습니다 (테스트로 확인)
  - 정원 마감과 동시 참여 처리 (두 명이 마지막 자리를 동시에 요청하는 경우)
- 제외: 비밀번호 방, 방장 위임·공지 (Figma에 없음)
- 완료 기준: 방 CRUD, 바로 참여와 승인 참여가 모두 동작, 정원 초과 참여가 불가능

## Phase 4 — 방 채팅 → `v0.4.0` = **MVP**
- [필수] 방 그룹 채팅: 텍스트 메시지, 입장·퇴장 시스템 메시지, 모임 정보 카드
- [필수] My chats: 대화 목록(마지막 메시지, 안 읽은 수), 빈 상태 → 홈으로
- [필수] Room menu: 참여자 목록, 나가기
- [권장] 방별 알림 끄기, 사진 보내기
- [선택] 위치 공유, 메시지별 안 읽은 사람 수
- 서버: WebSocket(STOMP) + JWT 인증, 방 멤버만 구독 가능, Redis Pub/Sub, 이전 메시지 커서 조회, 읽음 처리
- 앱: 재연결·재전송, 대화 캐시
- 완료 기준: 폰 두 대로 실시간 대화, 앱을 다시 켜도 대화 유지 → **과제 필수 요구사항 충족**

## Phase 5 — 친구 · 노크 → `v0.5.0`
- 제안: **친구 요청과 노크를 하나로 합칩니다.** 노크 = 짧은 메시지를 담은 친구 요청이고, 수락하면 친구가 되면서 1:1 대화가 시작됩니다. ([결정할 것](#결정할-것) 4번)
- [권장] Find friends: 추천 / 내 친구 / 받은 노크 탭
- [권장] 추천 알고리즘(직접 구현): 관심사 겹침 + 언어 교환 궁합(내가 배우는 언어 = 상대가 쓰는 언어) + 최근 활동, 차단 사용자 제외
- [권장] 친구 프로필, 노크 보내기 시트, 받은 노크 수락·거절, 1:1 대화(Phase 4 채팅 재사용)
- [선택] 보낸 노크 취소, 차단
- 서버: `knocks`(상태: 대기/수락/거절/취소), `friendships`, 1:1 대화방 생성
- 완료 기준: 추천 알고리즘 단위 테스트, 노크 → 수락 → 1:1 대화 흐름 동작

## Phase 6 — 안전 · 푸시 알림 → `v0.6.0`
- [권장] 신고(방·메시지·노크)와 관리자 처리. 익명 메시지도 관리자는 실제 작성자를 확인할 수 있습니다
- [권장] FCM 푸시: 새 메시지, 새 노크, 노크 수락, 모임 알림, 가입 승인·반려. Phase 2의 알림 설정과 연결
- [선택] 메시지 번역(외부 번역 API), 비밀번호 재설정, 금칙어 필터
- 완료 기준: 앱을 종료해도 푸시 수신, 신고 → 관리자 처리 흐름 동작

## Phase 7 — 운영 배포 · 품질 · 출시 → `v1.0.0`
- 운영: HTTPS, main에 합치면 자동 배포, DB 백업
- 품질: 부하 테스트, 오류 로그 수집, **Figma 다크 모드·한국어 화면과 대조**, 접근성 점검
- [선택] 스티커 프로필 보드 고도화
- 출시: 서명된 APK/AAB, README, 시연 영상, 발표 자료

## 기간이 모자랄 때 빼는 순서
아래 순서로 뺍니다. **Phase 1–4의 [필수]는 끝까지 지킵니다.**
1. 모든 [선택] 기능 (기능 스위치로 끄기)
2. Phase 6 전체 → 신고 버튼만 남기고 관리자는 DB에서 직접 확인
3. Phase 5 축소 → 추천 탭과 노크 수락 → 1:1 대화만
4. Phase 4·3의 [권장] (사진 보내기, 알림 끄기, 검색)
